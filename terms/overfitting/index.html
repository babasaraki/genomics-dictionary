Overfitting

Bioinformatics and statistics Published

Definition

Overfitting happens when a model learns the particular noise of the data it was trained on instead of the pattern that generalises. Such a model performs impressively on its training data and poorly on anything new. It is a constant hazard in genomics, where datasets typically contain far more measured features than samples.

Technical explanation

A model with enough flexibility can fit any finite dataset perfectly, including its random variation. The symptom is a widening gap between training and held-out performance as complexity increases. Remedies include regularisation, which penalises complexity; reducing the number of features considered; increasing the number of samples; early stopping; and ensembling. Honest evaluation requires held-out data that played no part in any choice made during model development, and in practice overfitting most often enters through the selection process rather than the model itself: choosing features using the whole dataset before cross-validation, tuning hyperparameters on the test set, or trying many model variants and reporting the best. Correlated observations compound the problem, because a random split can place near-duplicate samples on both sides. The same logic applies beyond machine learning: a polygenic score built and evaluated in one cohort will show inflated performance, and effect estimates from a discovery sample are systematically larger than those obtained on replication. A validation set used repeatedly gradually becomes a training set.

Practical example

A student builds a classifier of tumour subtype from expression data and reports near-perfect cross-validated accuracy. The features were selected by testing all genes against the labels using the entire dataset before cross-validation. Moving selection inside the cross-validation loop drops accuracy substantially, and the honest figure is the one reported.

Common misunderstanding

Cross-validation is widely believed to rule out overfitting. It does so only for choices made strictly inside each fold. Feature selection, normalisation fitted on all samples, batch correction, or repeated tuning against the same held-out data all leak information across the split and restore the optimism that cross-validation was meant to remove.
