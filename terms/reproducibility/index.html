Computational reproducibility

Bioinformatics and statistics Ethics and data governance Published

Definition

Computational reproducibility means that someone else, given the same data and the same description of the analysis, obtains the same results. It is a weaker and more achievable goal than replication, which asks whether a finding holds in a new experiment with new samples. Reproducibility is about the transparency of the computation, not about whether the conclusion is true.

Technical explanation

Achieving reproducibility in genomics requires several things together: the input data deposited in an archive under an accession, the analysis expressed as code rather than as interactive clicks, software versions pinned through environment specifications or container digests, reference genome and annotation builds recorded explicitly, random seeds fixed where stochastic methods are used, and the whole lot tracked in version control with a citable release. Workflow managers help by making the step graph explicit and the execution portable. Perfect bitwise identity is not always attainable, since multithreading can change floating-point summation order and some tools depend on hardware instructions, so the practical standard is that scientific conclusions are stable rather than that every byte matches. The common failure modes are mundane: an undocumented manual filtering step, a reference file that has since been replaced at the same path, a tool installed from a moving channel, and parameters recorded in a methods section as defaults when the defaults have since changed. Reproducibility is also a prerequisite for meaningful review, because an analysis that cannot be rerun cannot be checked.

Practical example

A team revisits an expression analysis published three years earlier in order to extend it. Because the repository pins the annotation release, the container digest and the random seed, the original figures regenerate exactly, and the new samples can be added with confidence that any change in the results comes from the data rather than from the software.

Common misunderstanding

Depositing code is often equated with making an analysis reproducible. Code alone rarely suffices: without the data, the software versions, the reference build and the parameters actually used, a script may not run at all, or may run and give different numbers. Reproducibility also says nothing about whether the method was appropriate.
