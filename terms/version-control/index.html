Version control

Bioinformatics and statistics Published

Definition

Version control is a system that records the history of a set of files, who changed what, when and why. Each saved state can be recovered, differences between states can be inspected, and parallel lines of work can be developed and then merged. In genomics it is applied to analysis code, workflow descriptions, configuration and documentation.

Technical explanation

Modern version control is distributed: every clone holds the full history, and commits are identified by a hash of their content, so a specific state of an analysis can be cited unambiguously. Branches allow a new method to be developed without disturbing the pipeline in routine use, and merges bring the work back together with an explicit record of the change. Hosting platforms add review workflows, in which a proposed change is discussed and approved before it is accepted, and automated checks that run tests on every submission. This matters beyond software: an editorial process for curated content, a protocol or a reference configuration can all be managed the same way, with the history serving as an audit trail. Limitations are worth stating plainly. Version control suits text, and handles large binary files and multi-gigabyte datasets poorly, so sequencing data belongs in an archive with an accession rather than in a repository. It also records only what is committed, so uncommitted local edits, manually installed tools and interactive steps remain invisible.

Practical example

A laboratory maintains its variant filtering thresholds in a version-controlled repository. When a result from six months earlier is queried, the team checks out the commit tagged for that analysis, reads the configuration in force at the time, and can show precisely which threshold changed and when it was reviewed.

Common misunderstanding

Version control is sometimes confused with backup. A backup restores files after a loss; version control explains how the files came to be as they are, attributes each change and lets alternatives be developed in parallel. It also protects nothing that was never committed, and it is unsuited to storing the raw data itself.
